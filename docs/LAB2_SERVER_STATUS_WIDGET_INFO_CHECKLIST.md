## 六、当前结论与风险汇总

### 已确认的产品方向

- LAB-2 状态与现有 `NOW / 正在进行` 组件合并，不新增占据首屏的大型独立卡片。
- NOW 内的任务区域采用有限高度和局部纵向滚动；组件标题、状态提示和“已归档”入口保持固定。
- 首页只回答三个问题：服务器是否在线、当前是否有实验运行、资源与健康状态是否正常。
- `/lab-status/` 作为完全公开的脱敏详情页。
- 公开展示 `MMdedup-v2` 和友好的实验阶段名称，隐藏内部标识。
- 不展示最近一次实验结果摘要，也不在本组件中添加历史实验博客链接。
- 首页只显示当前状态和最后更新时间；最近 60 分钟心跳只放在详情页。
- 独立 Cloudflare Worker 提供同域 `/api/lab2/status*`，使用 Cloudflare KV 保存最新状态和最多 60 个心跳点。
- LAB-2 每 60 秒上报、页面每 30 秒刷新、3 分钟未上报为 `STALE`、10 分钟未上报为 `OFFLINE`。

### 授权状态

- 已允许在 LAB-2 部署只读采集脚本和持久运行的 `systemd timer`。
- 已允许创建和部署 Cloudflare Worker、KV、Secret 与状态 API 路由。
- 已允许联调时暂时停止新采集器以验证 `STALE / OFFLINE`；不得影响实际实验。
- 所有产品决策与操作授权问题均已确认，实施时只需实时验证账户权限和服务器状态。

### 主要实施风险

1. **Cloudflare 权限风险**：如果没有 Worker、KV 和域名路由权限，只能完成本地前端样板，无法形成公网实时数据链。
2. **状态语义风险**：服务器在线、实验运行和 GPU 使用是三个不同状态。页面必须允许“服务器在线、实验运行中、GPU 空闲”同时成立，不能合并成一个模糊的“正在运行”。
3. **权威进度风险**：统一状态层尚未实现。只有明确取得 `completed / total` 时才显示进度；否则只显示运行状态和时长。
4. **过期数据风险**：浏览器缓存、网络中断或服务器时钟偏差可能让旧数据看起来仍然在线。新鲜度必须由服务端计算，并始终显示最后更新时间。
5. **隐私风险**：公开 JSON 必须使用字段白名单，禁止返回 IP、SSH 别名、用户名、内部路径、真实 unit/container 名、命令和日志。
6. **局部滚动风险**：内部滚动可以节省空间，但可能让访客忽略下方内容。实现时需要明确的滚动提示、键盘可访问、移动端触控顺畅，并避免页面滚动与组件滚动互相抢夺。
7. **运行环境误报风险**：LAB-2 的 `systemd --user` 当前存在历史失败 unit，不能直接把整体 `degraded` 判定为服务器异常；采集器只能检查明确白名单内的实验服务。
8. **路由冲突风险**：独立 Worker 只能绑定 `/api/lab2/status*`，部署前必须确认不会覆盖现有 `/api/views/track` 或站点其他请求。
